# 小满账号与同步

本机模式可以直接记账，不需要登录或体验码。账号模式让同一个人的账目、对话和分类偏好在不同设备使用。

## 当前开放范围

账号同步主体已完成合成账号验收，Vercel后端和[PR24网页](https://molly-gith.github.io/xiaoman-ledger/previews/pr-24/#/)均已发布，CI通过。已有已确认邮箱的账号可使用登录流程；新增注册只面向个人试用，不代表公众都能注册。

本人已登录后台，邮件返回地址已从旧开发地址改为 `https://molly-gith.github.io/xiaoman-ledger/previews/pr-24/`，只允许这一条精确返回网址。自有邮件服务（Custom SMTP）尚未启用；默认邮件服务只接受项目组织团队成员的邮箱。Molly 可使用登录 Supabase 后台的同一邮箱注册小满账号，其他未授权邮箱会收到明确提示。这个限制来自 [Supabase 官方邮件说明](https://supabase.com/docs/guides/auth/auth-smtp)。

实际确认邮件是否到达收件箱还没有测试。公开注册仍等待邮件服务方案选择；本轮没有购买服务、增加费用或要求复制密钥，邮箱确认保护保持开启。

已发布页面的320px隔离浏览器检查通过，注册入口及“等待邮箱确认”使用一次模拟注册验证，没有创建真实账号或发送邮件；本机合成账目和对话刷新后保留。这个页面检查不替代本人收件确认。

## 首次个人试用

当前已发布版本可按以下步骤使用：

1. 打开 PR24 体验页，到「我的 → 使用账号 → 注册新账号」。页面会注明“当前仅支持已获授权的体验邮箱注册”。使用你登录 Supabase 后台的同一邮箱，为小满设置密码；不要把密码或邮件确认链接发到对话中。
2. 若收到确认邮件，打开其中的确认链接；它应返回同一个 PR24 页面。按页面状态登录或继续使用，核对显示的是自己的邮箱。
3. 若邮箱未授权或邮件未到，不要反复提交。保留本机模式继续记账，待确认邮箱资格或邮件服务配置后再试。当前没有承诺邮件一定送达。
4. 登录后要带上旧账，再按下文预览并确认复制。仅登录不会上传本机数据。

## 平时怎么用

1. 到「我的 → 使用账号」输入自己的小满邮箱和密码。登录后页面会显示当前账号；个人、家庭、旅行账本仍各自独立。
2. 记账和修改偏好时直接保存到该账号。另一台设备登录同一账号即可读取；已经打开的页面可点「重新同步」。目前没有后台实时推送，也不在离线时假装保存成功。
3. 退出后回到原来的本机账本。云端账目不会复制到游客区；再次登录仍可以读取。

## 原来本机的账怎么办

首次登录的空白账号，在「我的」点击「复制本机数据到这个账号」。先看三个账本的账目、对话和偏好数量，确认当前邮箱无误，再确认复制。四份数据一次保存，本机原件保留。

复制不会自动发生。如果账号已有任何保存记录，这个入口会拒绝覆盖；需要合并或替换时，先分别备份，再使用明确提示替换范围的备份导入。预览后在别处新写入云数据也会阻止覆盖。

## 一句话的完整过程

以账号模式中的“这个月餐饮花了多少”再追问“跟上个月比呢”为例：

1. 网页从当前账号读取账本，只把当前账号、当前账本的对话作为记忆。
2. 常见说法由程序直接识别；复杂表达才交给 Dify 理解，提供本次文字、最近八条对话和查询条件。
3. Dify 返回日期、分类、比较方式等查询计划；网页先检查计划，再从当前账本逐笔计算金额。模型不会凭历史回答捏造金额。
4. 答案附带日期范围和账本名称；本账本最近四十条对话保存到当前账号，换设备后可以继续。
5. 若是“今天午饭35元”，先给待保存草稿；只有确认保存才记账。自己的银行卡之间划转不算新增收支，目前不支持独立转账记录，会直接说明。

账号、保存位置和同步属于网页与数据库，不是隐藏在 Dify Prompt 中的权限判断。Dify 仍是可读的七个中文节点，流程见 [中文工作流指南](dify/assistant-v2-workflow-guide.md)。

## 出问题时看哪里

- 提示“其他设备已更新”：重新同步，核对最新数据后再操作，不覆盖新版本。
- 提示“保存未能确认”：可能网络中断发生在保存之后，先重新同步核对，避免重复记账。
- 云端无法读取：仍显示当前账号，可以重试或退出到本机；不会把空账本伪装成云端成功结果。
- 对话和偏好可以单独清除；清除对话不会删除账目。完整数据清空和备份恢复都会明确说明作用于本机还是当前账号。

## 维护说明

新增表 `xiaoman_user_resources` 只允许登录者读写自己的四种资源，所有者来自服务器校验后的登录身份。额外的预期账号参数防止切号后旧请求误写。每次修改需要匹配版本；批量复制和三本记忆导入在同一事务完成。数据库检查权限、版本、大小和基本格式，网页再做完整业务格式校验。

本次迁移采用新增表与函数，未改旧账表、未自动搬运任何已有账目。迁移已通过连接器应用；本地文件编号与远端 `20261025021127` 一致。早期历史迁移文件与远端编号并不一一对应，不应直接将全部历史文件重新执行。

Site URL 与唯一 Redirect URL 均为上述 PR24 地址。无效令牌的只读返回测试已核对：允许的地址返回 PR24，外部地址被回落到同一 PR24；这没有发送邮件，也不能替代收件和确认流程验证。测试使用的两个合成账号已按精确 ID 与测试标记清理，剩余匹配数为零，临时凭据文件已删除。
