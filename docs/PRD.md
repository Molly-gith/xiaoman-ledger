# 小满 Web MVP PRD V0.2

## Goal

验证“财务周期 + 本周期可支出 + 消费/浪费/投资 + 过程反馈 + 周期复盘”是否能帮助普通职场人更有意识地管理工资收入。

## Product positioning

小满是围绕真实工资周期进行资金规划、记账、反馈和复盘的 AI 财务管理助手。

## Target user

有相对稳定工资收入，希望存钱、改善财务状况，但缺乏系统财务管理方法的职场人。

## P0 problems to validate

1. 用户是否需要一个比“已花多少”更直接的 **本周期可支出**。
2. **消费 / 浪费 / 投资** 是否能帮助用户理解消费价值，而不只是消费类别。
3. **消费过程中反馈** 是否比月底事后报表更能促进有意识决策。

## Core loop

`工资到账 → 建立财务周期 → 采用/调整本周期结构 → 消费/记账 → 更新本周期可支出 → 关键节点反馈 → 周期复盘 → 下一周期调整`

## Information architecture

`首页 | 账单 | + | 复盘 | 我的`

### 首页

- 本周期可支出（第一视觉层级）
- 距下次发薪天数
- 消费 / 浪费 / 投资结构与目标反馈
- 小满当前反馈
- 最近账目

### + 记账

双轨：

- 手动极速记账：金额 → 消费分类 → 消费性质 → 保存
- AI 自然语言记账：说/写一句 → AI 结构化 → 用户确认/修改 → 保存

**不要求用户选择支出来自哪个“资金桶”。** 房租、水电等固定支出发生时与其他支出一样正常记账。

### 账单

账目列表、收入/支出筛选、编辑、删除、查看消费性质。

### 复盘

周期收入、支出、消费/浪费/投资结构、基础财务健康检查、AI关键洞察、下一周期建议。

### 我的

发薪日、周期规则、结构偏好、数据备份/恢复、基础设置。

## Core business rules

### Financial cycle

用户设置常规发薪日，例如每月 20 日，则周期默认为当月 20 日 → 次月 19 日。

若当前周期没有记录固定工资，不直接判断失业；提示用户确认收入状态。

### Nature structure V0.2

默认参考结构：

- **消费约 70%**：正常生活的参考空间，不要求刚好花到 70%。
- **浪费 ≤ 5%**：提醒上限，不展示成“剩余可浪费额度”。
- **投资 ≥ 25%**：面向未来的保护目标，可包含储蓄、长期资产、学习、健康等。

三类不是三个独立钱包；产品不要求用户为了满足比例而把钱花完。

### Period spendable V0.2

新周期使用确定性计算：

`本周期可支出 = 本周期收入 - 消费实际 - 浪费实际 - max(投资目标, 投资实际)`

含义：

- 投资还没完成目标时，仍为目标保留空间。
- 投资实际超过目标时，反映真实支出。
- 投资目标与实际投资不会重复扣减。
- 房租、水电等不需要提前预留；发生时按实际账目进入消费/浪费/投资结构。
- 由确定性代码计算，禁止 LLM 直接计算。

对 CR-001 之前已经建立的旧周期，继续沿用旧计算，避免升级时历史金额突然变化；用户调整该周期结构或进入新周期后使用新模型。

### Expense nature

用户展示完整名称：

- **消费**：正常生活必要或合理支出
- **浪费**：低价值、冲动、重复或明显后悔型消费
- **投资**：面向未来能力、健康、储蓄或长期价值的投入

AI只给建议；用户最终确认。

## Recurring expense learning

MVP 不要求提前录入“固定支出”。

后续版本可以基于真实历史账目识别房租、水电、保险等周期性支出，并在置信度足够时询问：

> 我发现你通常会有一笔约 ¥X 的住房支出，要把它作为下个周期的参考吗？

AI只能建议，不能擅自创建用户义务或更改预算。

## Feedback system

### L1

正常记账：`已记账 · 本周期可支出 ¥X`

### L2

浪费接近上限、剩余天数和支出进度不匹配等；不阻塞操作。

### L3

仅用于明显值得关注的情况，例如大额非计划消费导致本周期可支出显著下降；提示后果，不阻止用户继续。

## Cycle review

- 最多突出 3 个关键洞察。
- 展示消费 / 浪费 / 投资实际结构与目标差距。
- 下一周期建议支持确认后带入下一周期。

## Xiaoman character

唯一核心角色。人格：温暖、聪明、克制、有一点调皮、不说教。

MVP重点出现在 Onboarding、关键反馈、周期复盘、成就节点。

## Base achievements

- 第一笔真实记账
- 第一个完整周期
- 第一次完成结构目标
- 第一次完成投资/储蓄目标
- 第一档长期积累里程碑

## Out of scope

- 要求用户提前维护房租/账单预留清单
- 自动抓微信/支付宝支付
- 银行余额自动同步
- 完整资产负债
- 家庭共同账户
- 荐股/基金推荐
- 复杂角色商城
- 高复杂度多 Agent

## Acceptance principles

- 核心财务计算正确率 100%。
- AI失败时必须可切回手动路径。
- 主流程完整覆盖：计划 → 记账 → 反馈 → 复盘。
- 所有主观 AI 判断可解释、可修改。
- 普通用户不需要理解 `necessaryReserve`、`spendKind` 等内部数据结构。
