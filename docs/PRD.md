# 小满 Web MVP PRD V0.1

## Goal

验证“财务周期 + 安心可花 + 消费/浪费/投资 + 过程反馈 + 周期复盘”是否能帮助普通职场人更有意识地管理工资收入。

## Product positioning

小满是围绕真实工资周期进行资金规划、记账、反馈和复盘的 AI 财务管理助手。

## Target user

有相对稳定工资收入，希望存钱、改善财务状况，但缺乏系统财务管理方法的职场人。

## P0 problems to validate

1. 用户是否需要一个比“已花多少”更直接的 **安心可花**。
2. **消费 / 浪费 / 投资** 是否能帮助用户理解消费价值，而不只是消费类别。
3. **消费过程中反馈** 是否比月底事后报表更能促进有意识决策。

## Core loop

`工资到账 → 建立财务周期 → 安排本周期的钱 → 消费/记账 → 更新安心可花 → 关键节点反馈 → 周期复盘 → 下一周期调整`

## Information architecture

`首页 | 账单 | + | 复盘 | 我的`

### 首页

- 安心可花（第一视觉层级）
- 距下次发薪天数
- 本周期预算进度
- 消费 / 浪费 / 投资结构
- 小满当前反馈
- 最近账目

### + 记账

双轨：

- 手动极速记账：金额 → 消费分类 → 消费性质 → 保存
- AI 自然语言记账：说/写一句 → AI 结构化 → 用户确认/修改 → 保存

### 账单

账目列表、收入/支出筛选、编辑、删除、查看消费性质。

### 复盘

周期收入、支出、储蓄、消费结构、基础财务健康考试、AI关键洞察、下一周期建议。

### 我的

发薪日、周期规则、预算偏好、早报频率、数据备份/恢复、基础设置。

## Core business rules

### Financial cycle

用户设置常规发薪日，例如每月 20 日，则周期默认为当月 20 日 → 次月 19 日。

若当前周期没有记录固定工资，不直接判断失业；提示：

> 这个周期暂时没有记录到固定工资，要更新一下你的收入状态吗？

### Safe-to-spend V0.1

`本周期可用收入 - 计划储蓄 - 必要支出预留 - 已发生可变支出`

- 由确定性代码计算，禁止 LLM 直接计算。
- 退款、信用卡未还、已承诺未来支出等复杂项暂列 TBD。

### Expense nature

用户展示完整名称：

- **消费**：正常生活必要或合理支出
- **浪费**：低价值、冲动、重复或明显后悔型消费
- **投资**：面向未来能力、健康、储蓄或长期价值的投入

AI只给建议；用户最终确认。

## Feedback system

### L1

正常记账：`已记账 · 安心可花 ¥X`

### L2

预算接近阈值、剩余天数和支出进度不匹配等；不阻塞操作。

### L3

仅用于明显值得关注的情况，例如大额非计划消费导致安心可花显著下降；提示后果，不阻止用户继续。

## Xiaoman Daily Brief

用户可选择：每天 / 工作日 / 仅关键变化 / 关闭。

优先展示：安心可花、剩余天数、昨日支出、当前消费结构；建议应尽量来自真实个人状态，不做随机理财鸡汤。

## LifeStatus V0.1

支持：稳定在职 / 新入职 / 涨薪 / 降薪 / 待业 / 收入不稳定 / 恢复就业。

AI可以发现异常，但状态切换必须用户确认。

## Cycle review

- 最多突出 3 个关键洞察。
- 基础财务健康考试。
- 下一周期建议支持确认后带入下一周期。

## Xiaoman character

唯一核心角色。人格：温暖、聪明、克制、有一点调皮、不说教。

MVP重点出现在 Onboarding、关键反馈、周期复盘、成就节点。

## Base achievements

- 第一笔真实记账
- 第一个完整周期
- 第一次完成预算
- 第一次完成储蓄目标
- 第一档储蓄里程碑

## Out of scope

- 自动抓微信/支付宝支付
- 银行余额自动同步
- 完整资产负债
- 家庭共同账户
- 荐股/基金推荐
- 复杂角色商城
- 高复杂度多 Agent

## Acceptance principles

- 核心财务计算正确率 100%。
- AI失败时必须可切回手动路径。
- 主流程完整覆盖：计划 → 记账 → 反馈 → 复盘。
- 所有主观 AI 判断可解释、可修改。
