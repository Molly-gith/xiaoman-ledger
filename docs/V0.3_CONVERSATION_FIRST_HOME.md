# V0.3 Conversation-first Home

## Why this change

Molly accepted the overall visual direction of the V0.3 AI-first shell, but the home screen still reads too much like a financial status dashboard with an AI entry point. The product promise is **小满——你的个人财务助手**, so conversation must be the primary interaction rather than a secondary action.

## Experience contract

### First screen

The first viewport should make it immediately obvious that the user can talk to 小满.

1. Keep the compact 小满 brand/header.
2. Show a conversation surface above the detailed financial dashboard.
3. Seed the conversation with a deterministic summary built from `AssistantFinancialSnapshot`.
4. Keep a visible composer/input on the first screen. The user must not have to press a separate “问小满” button first.
5. Offer 2–3 short starter prompts, such as:
   - 这周花多了吗？
   - 帮我复盘这个月
   - 我现在最该关注什么？

### Home capability cards

Add one-tap cards for existing product capabilities:

- **记一笔** → open the existing entry flow.
- **财务看板** → open the existing 财务 view.
- **账户与资产** → open the existing investment/account view.
- **周期复盘** → open the existing 复盘 view.

These cards are navigation affordances, not duplicate business logic.

## AI and financial-safety boundary

- `AssistantFinancialSnapshot` remains the only trusted financial-fact boundary for AI-facing UI.
- Amounts, ratios, investment contribution/gap, market value and P&L remain deterministic code outputs.
- The model may explain and guide; it must not silently recompute financial numbers.
- If Provider is not configured or fails, the deterministic summary, cards, manual bookkeeping, investment accounts and backup/restore remain usable.
- The UI must state the unavailable AI state honestly; no fake assistant response.

## Scope guardrails

This iteration does **not**:

- remove or redesign the whole bottom navigation;
- change the 70/5/25 finance model;
- change investment-account accounting rules;
- add bank/WeChat/Alipay sync;
- add LangGraph or multi-agent orchestration;
- run or fabricate a live-model accuracy baseline.

## Acceptance

- Conversation thread and composer are above the fold on the 小满 home screen.
- The composer is directly usable when a Provider is available, and has a clear disabled/degraded state when unavailable.
- The four capability cards are reachable with one tap/click and route to real existing functions.
- Financial numbers shown in conversation are sourced from deterministic facts.
- Existing bookkeeping, investment, migration, persistence and backup flows keep working.
- 320px mobile layout has no page-level horizontal overflow.
- Typecheck, lint, unit tests, build, Playwright and fixture eval all pass.
