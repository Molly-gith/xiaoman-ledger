# V0.3 Conversation-first Home V3

## Why this change

Molly's second-round experience gate kept the **AI personal finance assistant** direction but rejected the mobile interaction pattern: the traditional bottom tabbar is unnecessary, and the chat composer should sit at the bottom like a normal conversation product. Web and mobile should share one information architecture rather than feel like different products.

## Reference products

- **MonAi** — https://www.get-monai.app/
  - Borrow: focused natural-language entry and a minimal daily recording interface.
- **Cleo** — https://web.meetcleo.com/
  - Borrow: conversation is the primary product mental model; users ask about their own money in plain language.
  - Do not borrow: strong roast/judgmental personality.
- **Copilot Money** — https://www.copilot.money/ and https://www.copilot.money/faq
  - Borrow: calm data hierarchy; financial facts stay central; Web/iPhone/iPad/Mac share one product structure.
- **Piere** — https://www.piere.com/ and https://www.piere.com/savings-plan/
  - Borrow: AI assistant + clear next actions; AI proposes and the user stays in control.

A separate UI portfolio/showcase is no longer a required artifact. Future UX iterations should keep reference links plus explicit borrow / do-not-borrow notes, then validate the real Preview.

The current shortlist and implementation mapping are in [UI_REFERENCES.md](UI_REFERENCES.md).

## Experience contract

### Home

1. Keep the compact 小满 brand/header.
2. Show the conversation thread as the primary content surface.
3. Seed the thread with deterministic facts built from `AssistantFinancialSnapshot`.
4. Keep the four one-tap capability cards in the content area:
   - **记一笔**
   - **财务看板**
   - **账户与资产**
   - **周期复盘**
5. Do **not** use a persistent multi-tab bottom navigation.

### Bottom chat dock

- The composer stays visually attached to the bottom of the viewport on desktop and mobile.
- Starter prompts stay near the composer so the interaction reads like chat rather than a dashboard form.
- The page reserves enough bottom space that the dock never hides the last actionable content.
- Provider-unavailable state is explicit; the dock may remain visible without pretending a model response exists.
- The dock lives outside the conversation card. ResizeObserver reserves its measured height; VisualViewport moves it above the keyboard and hides starter prompts while the keyboard is open. The input remains 16px to avoid automatic focus zoom on mobile.

### Secondary pages

- 财务 / 复盘 / 我的 should not restore the old tabbar.
- Provide a lightweight **返回小满** route so secondary pages are not dead ends.
- 资产页 keeps its existing contextual back behavior.
- The old navigation markup and its CSS remapping have been removed. Return controls are in normal document flow, so they cannot overlap headings. Assets opened from Finance return to Finance.
- Settings and local backups remain reachable through two labelled header buttons. Finance also offers direct manual entry.

### Web / Mobile parity

- Use the same components, labels and IA at all viewport sizes.
- Responsive behavior may change spacing, card columns and widths only.
- Desktop can use a wider content column; mobile reflows the same hierarchy.
- 320px must have no horizontal overflow.

## AI and financial-safety boundary

- `AssistantFinancialSnapshot` remains the only trusted financial-fact boundary for AI-facing UI.
- Amounts, ratios, investment contribution/gap, market value and P&L remain deterministic code outputs.
- The model may explain and guide; it must not silently recompute financial numbers.
- If Provider is not configured or fails, deterministic facts, cards, manual bookkeeping, investment accounts and backup/restore remain usable.

## Scope guardrails

This iteration does **not**:

- change the 70/5/25 finance model;
- change investment-account accounting rules;
- add bank/WeChat/Alipay sync;
- add LangGraph or multi-agent orchestration;
- run or fabricate a live-model accuracy baseline.

## Acceptance

- No visible traditional bottom tabbar on the home screen.
- Chat composer is persistently reachable at the bottom on desktop and mobile.
- Four capability cards remain one tap/click away.
- Secondary pages retain a clear return path.
- Financial numbers shown in conversation are sourced from deterministic facts.
- Existing bookkeeping, investment, migration, persistence and backup flows keep working.
- 1440px / 390px / 320px all retain the same IA; 320px has no page-level horizontal overflow.
- Typecheck, lint, unit tests, build, Playwright and fixture eval all pass.
