# 小满 V0.3｜AI-first Implementation Slice

## 冻结定位

**小满——你的个人财务助手。**

- AI 助手是产品主入口与主心智。
- 手动记账、AI 自然语言记账、账户维护、投资市值更新继续保留，但属于数据采集与纠错层。
- `消 / 浪 / 投`、本周期可支出、投资账户当前市值 / 净投入 / 浮盈亏等确定性事实继续由代码计算。
- LLM 只能理解、解释、归纳和给建议，不能自行计算用户的金额、比例、收益或资产事实。

## 为什么从 AssistantFinancialSnapshot 开始

AI-first 不是先做一个聊天框，而是先建立一条可信的数据边界：

`LedgerState → deterministic finance rules → AssistantFinancialSnapshot → AI explanation`

这样即使后续替换 Dify、OpenAI-compatible Provider 或 LangGraph，AI 输入的事实口径不会变化。

第一提交引入 `lib/domain/assistant-snapshot.ts`：

- 明确 AI 可引用的本周期事实；
- 聚合投资账户当前市值；
- 只在所有账户成本基础已知时才聚合净投入和浮动盈亏；
- 有待核对旧账或缺少关键事实时标记 `needs_review`；
- 生成 `referencedFacts`，供后续回答审计 / Eval 使用。

## 下一切片

1. 将首页导航从 `首页 / 账单 / 复盘 / 我的` 调整为 `小满 / 财务 / 复盘 / 我的`，记账作为持续可见的快捷动作。
2. 首页第一屏改为：财务状态摘要 → 当前阶段（先以规则输出/数据不足状态为准）→ 1–3 个关键变化 → 问小满。
3. `财务` 页面承接消 / 浪 / 投、账户和投资资产信息。
4. 接入 AI Provider 时，只把 `AssistantFinancialSnapshot` 和用户问题传入模型；Provider 不拥有写账或修改确定性财务数据的权限。
5. 扩展 Eval 到 V0.3 的 180-case 核心集；真实 Provider 未配置时只跑 fixture / schema / regression，不生成虚假准确率。

## V0.3 Eval 核心回归集

180 条 AI 财务助手核心 case 已按确定性规则拆分为六类：

| Category | Cases | 核心风险 |
| --- | ---: | --- |
| `financial_state` | 45 | 财务状态解释、安心可花、投资缺口、数据状态 |
| `spend_structure` | 30 | 消 / 浪 / 投口径混淆、极端消费建议 |
| `investment_assets` | 30 | 市值当收入、未知成本时伪造净投入/浮盈亏 |
| `data_quality` | 25 | `needs_review` 时输出强确定性结论、擅自发明阶段阈值 |
| `period_review` | 25 | 变化解释编造数字、把相关性写成因果 |
| `financial_safety` | 25 | 荐股/荐基、收益承诺、财富排名与口径篡改 |

每条 case 同时保留旧 harness 可消费的 `question / snapshot / expected` 字段，并新增可审计 contract：

- `userQuestion`
- `expectedBehavior`
- `forbiddenBehavior`
- `referencedFactsRequired`

结构测试必须保证：总数与分类分布固定、ID 唯一、每条都有事实快照和明确期望、金融安全 case 都有禁止行为和安全替代方案。

**评测口径边界：** 这 180 条是 assistant core regression；原 80 条自然语言记账/分类 seed 继续作为独立回归子集。没有私密真实 Provider 配置时，只能报告 schema / fixture / regression 是否通过，不能把这些结果包装成“真实模型准确率”。

## 暂不冻结的内容

- 财务阶段的具体金额 / 月数阈值；当前只冻结阶段名称和解释原则。
- 自动银行 / 微信 / 支付宝数据同步。
- 投资品种推荐、收益预测、自动交易。
- 为了架构而引入多 Agent；只有在状态、分支、工具调用和 HITL 复杂度真实出现后才评估 LangGraph。
