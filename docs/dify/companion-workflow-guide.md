# 小满连续陪伴工作流

这版让小满能接着聊，也能依据当前账本给一句简短建议。它不会直接写账，也不会把聊天里提到的钱自动变成新账。

## 画布怎么读

1. **接收问题**：本轮文字、当地日期、本次会话最近最多 8 条消息；陪伴分支另带当前账本的有限汇总。
2. **区分陪伴 / 查账 / 旧版**：三个互斥分支。每次只运行一个模型节点。
3. **陪你聊一聊（只引用已知事实）**：先接住话题；记账时生成待确认草稿，查账时生成本机查询计划，普通聊天时给自然回复。
4. **汇合当前结果**：只接收本次实际执行的分支。
5. **检查意图与事实引用**：检查字段、日期、单一意图、引用是否属于本次摘要。后端还会检查数字、虚假保存声明和明显不合适的建议。
6. **返回给小满网页**：程序填入真实统计的中文事实，网页显示回复；保存仍需要用户确认。

原来的查账 V2 与更早版本分支保留原模型、提示词和输出结构。仍用 DeepSeek V4 Pro、temperature 0.2、thinking false；没有添加外部知识库、数据库读权限或第二次模型调用。

## 本次会话与历史的边界（补充实现，待发布验收）

网页刷新或重新打开后默认开始新对话；切到「账单」再回来保留本次会话，切换账本则开始该账本的新对话。网页只把本次会话成功保存的消息用于连续追问，不恢复旧历史中的补问或上一条查询。

「查看历史对话」只用于只读回看，可按日期查找；查看旧记录不会把它加入本次模型上下文，也不会重新激活待确认草稿。模型最多收到本次最近8条消息和必要摘要，Dify不负责自动检索全部历史。这个边界由网页控制，本次无需修改Dify输入协议或云端存储结构。

账目、分类偏好和陪伴偏好单独持久保存；新对话不清除它们。提醒仍查完整历史中的提醒编号去重。“聊天原文保留90天”仅为建议，本次不按天数删除、清理或隐藏旧历史。

## 数字怎么保证口径

模型不能自由写金额或计算“几顿饭”。它只能在回复里写 `[[fact:day_expense_fen]]` 这样的事实槽位，后端根据程序事实生成完整中文句子。引用列表必须与槽位相同；无来源的数字不显示。

事实来自当前账本，包含日期已核对的已记收入/支出、用户确认的性质、可选预算、用户自行设定的参考金额。没有账目备注、账目 ID、其他账本内容或银行余额。日期待核对的旧记录单列；不据此下确定超额结论。投资性质支出不是投资收益。

用户设置午餐参考价后，程序可以算“今日已记支出合计相当于多少午餐的金额”，并标明只是参考、不建议省掉正餐。没有参考价时就不作比较；今日合计也不能被说成某杯奶茶。

## 提醒与聊天的区别

预算达到八成、超过额度，或已记日支出超过用户自己设的日目标，由本机程序产生提醒，不额外调用模型。提醒有稳定编号供页面去重，支持关闭和静音。零日目标合法；没有设置日目标就是未知。页面内提醒不等于关闭网页后的推送。

聊天口吻支持温和、轻调侃、直接。调侃行为，不羞辱人；不编造饮食健康效果，不擅自判成浪费。模型不能声称已保存、已到账或已记住。有限上下文也不等于完整长期记忆。
