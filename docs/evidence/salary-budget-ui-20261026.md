## 范围与计算口径

- 入口位于「记账」页的可折叠薪资预算，默认关闭。不开启仍能记账；账单默认自然月。
- 预计税后薪资与消费/浪费/投资百分比分开设置，比例最多两位小数，合计不超过 100%。百分比为唯一配置来源；金额由整数分和基点计算，余下显示未分配。浪费 0 合法，未设置不等于已设置 0。
- 发薪日选填，默认 null；自然月不要求发薪日。配置后可选预算工资周期；预算启用且发薪日存在时，账单出现工资日周期筛选，支持前后期与本期。短月钳位至月末。
- 薪资及临时薪资只作预算基数，不生成工资收入、交易或旧财务周期。统计按支出日期，包含 cycleId 为 null 的账目，不重绑历史账目。
- 消费/浪费已用达到 80% 进入轻提醒，超过 100% 进入超限；同档持续显示，不每笔重复弹出。提醒为页面内状态和保存后跨档提示，不包含系统通知或后台推送。
- 投资仅计性质为投资的支出，不合并投资账户 contribution、withdrawal、市值或收益；投资目标不按消费上限告警。
- 待核对日期与未分类支出分别统计笔数/金额，排除确定已用并抑制预算提醒。可能落在周期边界的旧时间戳保守保留为待核对。
- 本期 override 绑定完整起止日期，只在该期匹配生效；下一期恢复预计薪资。停用保留配置和账目。
- 个人/家庭/旅行独立保存；账号模式沿用现有身份校验、CAS 和云端 JSON，游客模式仍本机保存。完整 JSON 备份包含全部三本配置。
- 「我的」、账号帮助与隐私说明按需展开；复盘减少首屏说明，把收支、比较、分布与依据分层展开。此前已发布的日期复盘口径不改。

## 两项已修的 P2

1. **保存完成后，预算提醒计算异常不能变成“保存失败”。** 独立复核已复现大额累计溢出触发此问题。现将提醒计算单独捕获；仓储保存成功仍返回成功、更新页面，计算问题由预算面板说明，避免用户再次保存导致重复记录。
2. **同步或跨期后，编辑表单不能沿用旧设置。** 普通预算表单按完整 settings 重建；本期调整同时按 settings 和当前起止日期重建。避免同步后覆盖新配置，或把前一期草稿保存为新一期调整。代码已修，午夜跨期浏览器用例已通过；同步更换配置后的表单key由独立审查复核。

## 兼容性与保留事项

LedgerData 新增 salaryBudget，仍使用 v4。新版读取旧 v4 缺失字段时归一为 null；v1–v3 迁移也默认关闭。该字段已加入账本快照、切换、备份与云端归一逻辑。现有数据库 ledger JSON 约束允许新增键，无需数据库迁移。

旧版 v4 客户端的 inactive 账本字段白名单不认识 salaryBudget，会拒绝读取新保存格式，而不是继续写入并静默丢弃预算；原账目保留。旧标签页需要更新到本轮版本。此为技术兼容限制，不应向用户误称所有旧客户端都能继续编辑新备份。

保持原有账号待决事项：组织授权邮箱的真实收件与确认返回未验证；公开注册尚待 SMTP/邮件服务选择。本轮不变更邮件配置、不新增费用、不新增密钥。
